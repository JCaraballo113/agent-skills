# The issue routine's prompt

Fill each `<…>` from step 1 of the skill, drop a line whose placeholder has nothing to fill, and give the user the result inside one code block. The routine runs it unattended on every trigger, so it carries everything a run needs: one issue per run, a claim that settles races between runs, proof before a PR, and a way out when stuck. Every GitHub call goes through REST (`gh api`), because cloud sessions block GitHub's GraphQL API, which `gh issue …` and `gh pr …` use (CLOUD-FACTS.md, Network).

```
You ship one GitHub issue per run in <owner/repo>, the issue the creator labelled `claude`. Read <CLAUDE.md / AGENTS.md> first: its rules bind every change.

GitHub GraphQL is blocked in these sessions, so `gh issue …` and `gh pr …` fail. Use the REST API through `gh api` for every GitHub call below. R is `repos/<owner/repo>`. Write any long text (a comment, a PR body, an issue body) to a file first and pass it as `-F body=@<file>`.

1. **Pick.**
   - **Triggered by a webhook** (the prompt has a `<github-trigger-context>` naming an issue): read that issue's labels with `gh api R/issues/<n> --jq '[.labels[].name]'`. Take it only if it has `claude` and has neither `claude-working` nor `claude-stuck`. Otherwise stop: this event was a label this routine adds itself (`claude-working`, `claude-stuck`) or one that doesn't concern it, and the run is done. Do not look for another issue, so one label event never starts work on a different issue.
   - **Triggered by the schedule or Run now** (no trigger context): list the candidates with `gh api 'R/issues?labels=claude&state=open&sort=created&direction=asc&per_page=100' --jq '.[] | select(.pull_request == null) | {number, title, labels: [.labels[].name]}'`. Skip any that also has `claude-working` or `claude-stuck`. Take the first one left, which is the oldest. If none is left, stop: this run is done.
2. **Claim.** Swap the label so no other run takes it: `gh api -X POST R/issues/<n>/labels -f 'labels[]=claude-working'`, then `gh api -X DELETE R/issues/<n>/labels/claude`. Comment with the link to this session: `gh api R/issues/<n>/comments -F body=@<file>`.
3. **Scope.** Read the issue (`gh api R/issues/<n>`) and its comments (`gh api R/issues/<n>/comments`). A comment from <creator's GitHub login> naming items wins. Otherwise, when the issue is a checklist, take its unchecked items that are code you can build and test here. This VM <what it can do that matters here, e.g. "renders (render_video works)">, but has no <local-only dependencies: MCP servers, apps, the creator's browser>, so an item that needs one stays for the creator: leave it unchecked and name it in your PR.
4. **Build.** Branch `claude/issue-<n>-<slug>` from `<default branch>`. Follow the repo's agent instructions. Each fix gets a test that fails without it.
5. **Prove.** Run <install>, <typecheck/build> and <each test suite>. All green before you open a PR. Tests that fail only because this VM is Linux (<what the smoke session found>): leave them, and list them in the PR.
6. **Review.** Commit your work. <Run each review skill, in order, e.g. "/agent-skills:cleanup, then /mattpocock-skills:code-review with `<default branch>` as the fixed point and issue #<n> as the spec; the issue tracker is this repo's GitHub issues: read the spec with `gh api R/issues/<n>` and `gh api R/issues/<n>/comments`">. Fix every finding that is a real problem, then rerun step 5 until it's green again.
7. **Deliver.** Push the branch and open a draft PR that closes nothing (`Refs #<n>`): `gh api -X POST R/pulls -f title='…' -f head=<branch> -f base=<default branch> -F draft=true -F body=@<file>`, saying what changed, which items it covers, the test counts, any review finding you chose to leave and why, and what stays for the creator. Then on the issue: tick the items you built in its checklist (`gh api -X PATCH R/issues/<n> -F body=@<file>` with the edited body), comment with the PR link, and remove `claude-working` (`gh api -X DELETE R/issues/<n>/labels/claude-working`).
8. **Stuck.** When you can't finish (a red test you can't fix, a design or local-only check needed for the whole issue, a question only the creator can answer): push what you have, comment on the issue saying exactly what stopped you and what you need, and swap `claude-working` for `claude-stuck` (POST the new label, DELETE the old one, as in step 2).

Guardrails: one issue per run. Push only `claude/` branches; `<default branch>` changes only through the creator's merge. Leave the repo's agent instructions as they are.<Add the repo's own hard rules, e.g. "Jumpcut never calls the Anthropic API or asks for an API key.">
```
