# The morning board routine's prompt

The morning board is the creator's one daily read: a phone-sized board (what waits on them, what happened overnight, what's in progress) and a card for each new decision or design sign-off. Each line is spoken by the Claude bot whose role it reports ([bots/](../bots/), SKILL.md's Roles), and in a Claude Project the board posts as a widget with each bot animated in its mood. It turns the gate's `Decision:` blocks and the design pass's `needs-signoff` issues into cards, and applies the creator's answers as `Released by the creator:` on a PR or `Design signed off:` on an issue, so the gate and Ship pick them up on their next runs. It judges, builds and merges nothing.

**Trigger.** A scheduled role (SKILL.md, step 5), daily at the hour the creator picks, a minute off :00 and :30. The coordinator (outside a Project, a fresh session per fire) runs the cheap check below and starts a fresh thread on the filled prompt (e.g. `/mnt/project-files/agent-team/prompts/morning-board.txt`) only when it finds work. In a Project the thread can't post in the project chat, so it hands the board and cards to the coordinator, which posts the board with `post_widget`, the cards with `ask_decision`, and relays each answer back for the thread to apply; outside one, the session sends the board as Markdown in its final reply.

**Cheap check.** A PR merged since the last board; an open issue or PR labelled `needs-hitl`, `needs-signoff`, `claude-stuck`, `main-red`, `claude-working`, `claude-ready` or `needs-design`; or an open, ready PR from a `claude/` branch.

**Fill.** Each `<…>` that names something about the repo, from the survey; placeholders a run fills as it goes (`<n>`, `<sha>`, `<date>`, `<iso time>`, `<board>`, `<board title>`, `<page>`, `<board link>`, the board's JSON and Markdown shapes in steps 3 and 4, and the answer shapes at the end) stay as written. The board state file must outlive the thread: in a Project, the project's files (e.g. `/mnt/project-files/agent-team/board-state.json`); outside one, a session's files go with it, so keep the state where the next session can read it, such as the body of one pinned issue. Without a design hand-off, drop the sign-off lines and Doodle's. In a Project, copy [bots/art.mjs](../bots/art.mjs) and [bots/board-widget.mjs](../bots/board-widget.mjs) into the shared folder beside the prompts (e.g. `/mnt/project-files/agent-team/bots/`) and fill `<bots folder>` with it, and `<board folder>` with a folder beside it for each day's board (e.g. `/mnt/project-files/agent-team/board`). Outside one, keep the sections and the bots but drop step 3's file and render and step 4's widget, since only a Project's coordinator can post a widget.

**Ask the creator** what time the board should arrive.

```
The morning board for <owner/repo>: one post the creator can answer from their phone, built from GitHub (`gh api`, REST only; R is `repos/<owner/repo>`; write any long text to a file first and pass it as `-F body=@<file>`). In a Claude Project, the coordinator session posts it, since it owns the project chat; you build it in a fresh thread the coordinator starts each morning. Outside a Project, you are a fresh session and post it yourself. What was carded before is in <board state file, e.g. "/mnt/project-files/agent-team/board-state.json"> ({"carded": {"pr-<n>@<sha>" | "issue-<n>-signoff": "<date>"}, "lastBoard": "<iso time>"}); read it first and write it back at the end.

1. **Gather.**
   - Merged since `lastBoard`: PRs into `<default branch>` closed as merged.
   - `<default branch>`: green, or each open `main-red` issue.
   - Stuck: open issues labelled `claude-stuck`, with the one thing each needs (from its last comment).
   - Decisions: open PRs labelled `needs-hitl`. For each, read its newest verdict. One whose verdict ends in a `Decision:` block and isn't carded at its head sha gets a card (step 2). One held without a `Decision:` block gets one line on the board saying what it waits on.
   - Sign-offs: open issues labelled `needs-signoff` not yet carded: each gets a card naming its board on <design tool>.
   - In progress, what is moving as the board goes out:
     - Shipping: open issues labelled `claude-working` (each is being built now), and how many are labelled `claude-ready` (queued behind them).
     - The gate's line: open PRs from `claude/` branches that are not drafts and not labelled `needs-hitl`, oldest first; note the count and the first three.
     - Conflicts: of those PRs, each whose `mergeable` is `false` (`gh api R/pulls/<n> --jq .mergeable`; the list call leaves it out).
     - Designs: open issues labelled `needs-design`, oldest first; tonight's design pass takes the first three.
2. **Cards.** Write each card as: the question (under 15 words), two to four options (label one or two words, consequence one sentence), which one is recommended and why, and a context line that opens with the bot asking (`Stamp ·` for a PR, `Doodle ·` for a sign-off) and then the PR or issue title and number. A PR card takes its question and options from the verdict's `Decision:` block. A sign-off card asks "Sign off the <board> board for #<n>?" with Sign off (recommended: the build starts) and Change it (the creator says what to change).
3. **Board.** Every line is spoken by the Claude bot whose work it reports, in the mood that matches, under one of three sections: `you` (a card waits on the creator), `overnight` (what happened since `lastBoard`), `now` (in progress).
   - `you`: Stamp, `ask`: a hold with a card. Doodle, `ask`: each board waiting for sign-off.
   - `overnight`: Stamp, `done`: what merged. Stamp, `stumped`: a hold without a card, saying what it waits on. Pulse, `done`: `<default branch>` is green at its sha. Pulse, `stumped`: each `main-red` issue. Bolt, `stumped`: each `claude-stuck` issue and the one thing it needs.
   - `now`: Bolt, `work`: each `claude-working` issue ("Shipping #n"), with the `claude-ready` count when there is one; with nothing shipping, Bolt, `nap`: "Nothing shipping" (and "nothing queued" when that's true too). Stamp, `work`: how many PRs wait for the gate and the next three. Mend, `work`: the PRs with conflicts. Doodle, `work`: how many issues wait for a board and tonight's three.
   Write the board to <board folder>/<date>.json as `{"date": "<date>", "lead": "<how many cards wait for the creator, whether <default branch> is green, and the gate's line>", "lines": [{"section": "overnight", "bot": "stamp", "mood": "done", "text": "Merged [#<n>](<PR url>) and [#<n>](<PR url>)."}]}`: one line per item above, every PR and issue as a Markdown link, under 12 lines; when it runs over, fold a section's lines of one kind into one line. Then render it: `node <bots folder>/board-widget.mjs <json> > <board folder>/<date>.widget.html`. It is done when the command exits 0 and the file is non-empty; a bad `section`, `bot` or `mood` makes it exit 1, so fix the JSON and rerun. When nothing merged, nothing waits on the creator, `<default branch>` is green and nothing is in progress, there is no board today: skip step 4.
4. **Hand over.**
   - **In a Claude Project:** get the coordinator's session with `get_channel_session_id`, then `send_message` it, in this order: the widget's HTML inline, the file's contents verbatim (its `<style>` block animates the bots, so it stays in) between a line `===WIDGET===` and a line `===END===`, followed by the file's path for the record (the coordinator can't read files, so the HTML must be in the message; when the file is over 50 KB, cut board lines until it fits); the board as plain Markdown (the lead, then each section's label, Needs you, Overnight or In progress, over its lines as `**<Bot>** <text>`), its fallback; and the cards. Ask it to post the widget in the project chat with `post_widget` (`family: "visualize"`, `widget: "show_widget"`, `input: {"title": "morning-board-<date>", "widget_code": <the HTML between the markers>}`, `text`: the lead), to post the Markdown fallback instead if the widget is refused, then each card with `ask_decision`, and to relay the creator's answers to this thread with their message attached. In this thread, refresh the status checklist only. With no board today, send the coordinator one line saying so and resolve this thread.
   - **Outside a Project:** end with the board as Markdown (the lead, then each section's label over its lines as `**<Bot>** <text>`) and each card's question, options and recommendation as your final reply, and send a push notification when this session can. The creator answers in this session. With no board today, end with one line saying so.

When the creator's answer to a card reaches you (relayed by the coordinator, or typed into this session), act on it the same turn:
- A PR decision: comment on the PR `Released by the creator: <the option they picked, and their words>`, then remove `needs-hitl`; the gate's next hourly run re-checks it with their answer as part of the spec.
- A sign-off: comment on the issue `Design signed off: <board title>, page <page>, <board link>`, swap `needs-signoff` for `claude-ready`. Change it: note their words on the issue, swap `needs-signoff` for `needs-design`, and the next design pass redraws it.
Then, in a Project, `send_message` the coordinator one line saying what you did, for it to post under the card; outside one, reply with that line.
```
